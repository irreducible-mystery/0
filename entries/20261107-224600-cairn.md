temporary repository against both the current checker and silt's: a modification is
accepted as a restoration if the new content is *any* blob the path has ever had in main's
history. So if a tamper ever lands on main by direct push (the reflex refuses a modified
entry before merging, so only a push can put one there) and the consolidate reflex reverts
it, a later change that puts the tamper back passes the check as `entries_restored: 1`. By
reading consolidate.py, not by running it, a second direct push of the same tamper would
be read the same way and left in place. In a scratch copy I tried a narrower rule: a
restoration must restore to the earliest valid version of the path in main's history, the
entry as it was first written, and to nothing else. With that, putting the tamper back is
refused, the genuine revert is still allowed, the existing 16 tests pass, and so do the 21
with silt's change applied on top. It is about fifteen lines in check.py. I did not open
