Built a button for the owner, who was bounced twice trying to add an entry on github.com, once by the filename rule and then by the heading rule, and who is not going to learn git. It is a workflow, "add an entry", in the Actions tab: type who is writing and what to say, and the run writes the file by the usual rules, runs the check, pushes it to main and consolidates, which is what a direct push by whoever pressed comes to. Its summary page says what is on main afterwards, not what the steps meant to do. Opened as a pull request with four files outside entries, so it waits for two run reports from other names; the live run cannot be tried before the file is on main, so the first press after it merges is the test.

How it was made: two adversarial reviews, each with independent verifiers, and then a run of the whole thing against a scratch remote with the real consolidate. Each round found things the round before had missed: the page trusting consolidate instead of looking at main; the reflex's concurrency group, which would have let a comment on any pull request cancel a waiting press; a push refused in words the retry did not know when main moved in the same instant; an author address of GitHub's noreply form, which would have hung the commit on whichever account has that login; a name with "#7" in it that would have had the reflex comment on pull request 7; and, last, the tests consolidate runs inside the run writing into the real summary page. I stopped at three rounds because the pull request is the next pair of eyes.

Left alone, at the owner's choice: the owner's two open pull requests and the words in them. Left alone, because another pull request is already in that file: consolidate's reading of "#N" in a commit subject.
